# Отчет за День 8: Собрал мониторинг — Prometheus, Alertmanager, Grafana

## Что было сделано

### 1. Разобрался, зачем мониторинг, и выбрал стек

Мониторинг собирает метрики со всех машин и говорит, если что-то упало.

Стек: **Prometheus** (собирает метрики) + **node_exporter** (агент на каждой машине, отдает системные метрики) + **Alertmanager** (развозит алерты) + **Grafana** (графики). Плюс **blackbox_exporter**, он проверяет доступность сайтов снаружи, как пользователь.

Ключевое решение: **централизация**. Метрики собираются на одной машине (control node, 130), экспортеры стоят на managed. Не надо на каждой системе свой Prometheus, один сервер тянет метрики со всех.

### 2. Grafana

Ставится как целое дерево (не отдельный бинарь), распаковываю в `/opt`, симлинк `/opt/grafana` для стабильного пути. Юнит:

```
ExecStart=/opt/grafana/bin/grafana server --homepath /opt/grafana
```

Datasource (Prometheus) **не тыкал руками в UI**, а положил файлом:

```yaml
apiVersion: 1
datasources:
  - name: Prometheus
    type: prometheus
    url: http://localhost:9090
    isDefault: true
```

Файл в `conf/provisioning/datasources/prometheus.yml`, Grafana читает его при старте. Импортировал готовый дашборд по node_exporter (ID 1860)

## Разбор ошибок

| Ошибка | Что я понял |
|---|---|
| `curl .../api/datasources` пусто | API Grafana требует авторизации. Смотреть надо с `-u admin:admin` или глазами в UI. |

## Итог

Теперь у меня есть **полноценный мониторинг**: Prometheus тянет системные метрики со всех машин, blackbox проверяет доступность сайтов, Alertmanager шлет алерты в Telegram, Grafana рисует графики. Всё ставится плейбуками, конфиги (datasource) - файлами. Т.е. мониторинг такой же код, как и всё остальное.
