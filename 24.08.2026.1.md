##  Чему я научился за День 2 (24.08.2026)

Сегодня я перешел от ручной настройки к автоматизации процессов и траблшутингу веб-серверов:
1. **Автоматизация инфраструктуры:** Написал первый Bash-скрипт автоматизации деплоя, разобрался с понятием шебанга (`#!/bin/bash`) и научился управлять правами на исполнение файлов (`chmod +x`).
2. **Контроль версий (Git/GitHub):** Освоил базовый рабочий цикл Git (связка локальной директории Nginx с репозиторием), поработал с токенами доступа (Personal Access Token).
3. **Управление правами доступа:** На практике разобрался с рекурсивной сменой владельца и группы для системных папок (`chown -R user:group`), решил проблему конфликта прав между веб-сервером и обычным пользователем.
4. **Безопасность и автоматизация привилегий:** Настроил беспарольный запуск (`NOPASSWD`) для конкретной системной команды (`systemctl reload`) через `visudo`, что позволило автоматизировать скрипт без потери безопасности всей системы.
5. **Диагностика и логирование:** Научился проводить безопасный аудит конфигурации веб-сервера без его остановки (`nginx -t`), освоил чтение системных логов через `journalctl` с использованием фильтров.

##  Траблшутинг-лог: Ошибки Дня и их Решения

### Кейс 1: Ошибка смены владельца
* **Симптомы:** После первой команды смены прав папка Nginx осталась недоступна для корректного клонирования репозитория.
* **Анализ:** Команда `chown` изменила только владельца, но оставила группу за рутом (`root`), плюс не были применены права суперпользователя для системной директории.
* **Фикс:** Использование `sudo chown -R leon:wheel /usr/share/nginx/html/`.

### Кейс 2: Падение веб-сервера
* **Симптомы:** Браузер выдавал ошибку `Connection Refused` при попытке зайти на localhost.
* **Анализ:** Команда `systemctl enable nginx` включает автозапуск сервиса при загрузке системы, но не стартует процесс в текущей сессии.
* **Фикс:** Запуск службы через `sudo systemctl start nginx`

### Кейс 3: Зависание в Neovim (Сбой горячих клавиш)
* **Симптомы:** Редактор выдал ошибку `E348: No string under cursor` и заблокировал ввод кода скрипта.
* **Анализ:** Ошибочный запуск `nvim` вместо `nano`. Привычные сочетания клавиш nano сработали в Vim как внутренние команды поиска слова под курсором на пустой строке.
* **Фикс:** Больше не пользуюсь нвимом.

### Кейс 4: Нарушение структуры Git-репозитория (`fatal: not a git repository`)
* **Симптомы:** Скрипт деплоя падал на шаге `git pull`.
* **Анализ:** При первичном клонировании команда `git clone` была запущена без точки в конце пути. В итоге Git создал подпапку внутри `/html/`, а корень веб-сервера остался без скрытой директории `.git`.
* **Фикс:** Полная очистка папки и клонирование напрямую в текущий рабочий каталог через `git clone <url> /usr/share/nginx/html/.`.

### Кейс 5: Ошибка инициализации visudo (`no editor found`)
* **Симптомы:** Команда `sudo visudo` падала с ошибкой отсутствия редактора `/usr/bin/vi`.
* **Анализ:** В базовой сборке Arch Linux отсутствует классический редактор `vi/vim`, к которому утилита обращается по умолчанию.
* **Фикс:** Переопределение переменной окружения редактора на лету: `sudo EDITOR=nano visudo`.
