#  Мой отчет за День 4: Настроил удобную и безопасную разработку

##  Что было сделано

### 1. Переехал с nano на VS Code (Remote-SSH)
* **Подключился к серверу из Windows**: Поставил на Убунту SSH-сервер, открыл порт 22 в файрволе и теперь захожу на виртуалку прямо из VS Code через плагин Remote-SSH. Больше не редактирую `docker-compose.yml` в консольном `nano`, а работаю в красивой среде.

### 2. Спрятал пароли базы данных (`.env`)
* **Вынес секреты из кода**: Раньше пароли и юзер БД лежали прямо в `docker-compose.yml` открытым текстом, и это уехало бы на Гитхаб. Заменил их на плейсхолдеры `${POSTGRES_PASSWORD}`.
* **Создал файл `.env`**: Сами значения теперь лежат в секретном файле `.env`, который Git не трогает (добавил в `.gitignore`). Docker Compose сам подхватывает оттуда переменные, и мне ничего вручную подставлять не пришлось.

### 3. Чинил Гит после того, как сломал его сам
* **Поймал битую базу Гита**: Вылезла ошибка-"empty object within `.git`" — файлы Git повредились (видимо, толкнул при резком отключении виртуалки). Поначалу хотел просто почистить, но хорошо, что запасся и не удалил весь .git сразу.
* **Восстановил через переклонирование**: Раз проект уже был на Гитхабе, сделал новый чистый клон, вернул на место `.env` и поднял контейнеры. Всё снова работает, ничего не потерял.

### 4. Разобрался с SSH-ключом для Гитхаба
* **Выяснил, почему пуш требовал пароль**: Ремоут почему-то был настроен через HTTPS, я переключил его на SSH.

## Что я решил не делать прямо сейчас

* **Не стал чистить историю Гитхаба**: Пароли из старых коммитов можно выпилить инструментом `git-filter-repo`, но для учебного проекта мне это не сдалось. `.env` + `.gitignore` уже закрыли утечку свежих секретов.
