# Мой отчет за День 6: Автоматизировал установку и деплой через Ansible

## Что было сделано

### 1. Разобрался, зачем Ansible, и поднял его

Понял главное: Ansible - это удалённый пульт для кучи серверов. Я пишу один файл, он выполняет команды на всех машинах сразу, и не важно, Ubuntu там или Debian.

Установил на control node, настроил inventory - список машин:

```ini
[ubuntu_servers]
vm2-ubuntu

[debian_servers]
vm3-debian

[all:vars]
ansible_user=leonlewiz
ansible_python_interpreter=/usr/bin/python3
```

Ключевой момент: **имена групп только с `_`**, дефисы Ansible не ест. Уяснил, что группы, это как теги: можно гонять команды на все машины (`all`), а можно только на Ubuntu или только на Debian.

### 2. Проверил связь и научился ad-hoc командам

Проверка, что до всех машин достучался:

```bash
ansible all -i hosts.ini -m ping
```

Потом ad-hoc - это разовые команды без плейбука. Поставил htop сразу на обе машины:

```bash
ansible all -i hosts.ini -m apt -a "name=htop state=present" -b
```

`-b` - это become (sudo).

### 3. Написал первый плейбук, установка Docker и поднятие сайта..

Плейбук можно посмотреть в репозитории my-nginx-site

### 4. Полезная диагностика

Научился смотреть, что реально живёт в базе:

```bash
docker compose exec db psql -U myuser -d postgres -c '\l'
```

Без `-d postgres` psql по умолчанию лезет в базу с именем юзера и падает `database myuser doesnt exist`.

## Разбор ошибок (чтобы не наступать на грабли)

| Ошибка | Что я понял |
|---|---|
| `couldn't resolve module/action 'clone'` | Написал `clone` вместо `copy`. В Ansible такого модуля нет. |
| `key is ignored as the file has an unsupported filetype` | Создал папку `docker.asc` вместо файла, ключ скачался внутрь папки. |
| `password authentication failed` | `DB_USER` (для бэкенда) ≠ `POSTGRES_USER` (роль, создаётся при первом старте тома). Совпали и заработало. |
| `database site_analytics does not exist` | `POSTGRES_DB` ≠ `DB_NAME`. База, как и роль, создаётся один раз. Привёл к одному имени и снёс том. |
| `fatal: database myuser doesnt exist` | psql без `-d` подключается к базе с именем юзера. Нужно `-d postgres`. |
| `Permission denied ... docker.sock` | Юзер не в группе `docker` на managed nodes. Запускать docker через `-b` (sudo), либо добавить юзера в группу. |

## Итог

Теперь у меня есть **набор плейбуков, который поднимает весь проект на любой чистой машине**: Ansible ставит Docker, копирует файлы проекта, поднимает контейнеры. Одна команда, и новая машина готова. Сейчас три сайта работают, у каждого своя база. Управление машинами тоже через Ansible: ad-hoc команды на `all`, `ubuntu_servers` или `debian_servers` — без захода по SSH на каждую.
