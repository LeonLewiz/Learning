# Отчет за День 11: Восстановил мониторинг с нуля

## Контекст

Сегодняшний день это проверка: **воспроизводится ли проект с нуля плейбуками**. Ответ: да, воспроизвёлся, но по пути нашёл и починил косяки, которые были.

## Что было сделано:

## Grafana - довёл дашборды до provisioning

Дашборд **Node Exporter Full** раньше работал кое как, вчера умер. Проверил **четыре слоя** одной проблемы:

1. **uid датасорса** - дэшборд ссылался на старый uid, датасорс генерил новый. Не совпадали → падение provisioning.
2. **`${ds_prometheus}`** - плейсхолдер из экспорта grafana.com, при provisioning не подставляется. Заменил на реальный uid.
3. **`$__rate_interval`** - Grafana не знала `scrape_interval`, окно считалось неверно → `rate()` пустой. Добавил `timeInterval` в datasource **и** `global.scrape_interval` в конфиг Prometheus. Оба `15s`.
4. **ссылка панели на datasource** - часть панелей смотрела на переменную `${ds_prometheus}`. Указал конкретный датасорс.

Дэшборд теперь лежит в репо, `allowUiUpdates: false` - источник только файл.

## Blackbox - проверка сайтов

Настроил через `relabel_configs`:
- `__param_target` - сложил `__scheme__` + `__address__` через сепаратор `://`
- `instance` - подписал метрику адресом сайта
- `__address__` - `127.0.0.1:9115`

Поначалу job был сломан и не работал. Теперь `probe_success` показывает живость обоих сайтов.

## Alerting - правила + доставка

Раньше алерты **вообще не были стандартизированы**. Сегодня собрал цепочку:

- `prometheus.yml.j2` - конфиг для прометея
- `alertmanager.yml.j2` - конфиг для алертменеджера
- Телеграм секреты теперь в `vault.yml`

## Volume для БД

Обнаружил при воспроизведении: сайт терял данные при `down/up`. Volume `pgdata` монтировался в пустую папку `/var/data/db`, а postgres пишет в `/var/lib/postgresql/data`.

## Разбор ошибок

| Ошибка | Что я понял |
|---|---|
| Дэшборд пустой, хотя JSON валиден | Проблема не в JSON, а в **несовпадении uid** и **неподставленных плейсхолдерах**. Проверять надо связи, а не только синтаксис запросов. |
| `probe_success` 400 Bad Request | Написал `module: [http_200]` вместо `http_2xx` из-за того что плохо читал документацию. |
| `send_resolver` / `cluster not found` | Опечатка в ключе + секция `cluster` не поддерживается конфигом в моей версии. Кластер выключил **флагом в юните**. |
| Данные БД не сохраняются | Volume был, но смонтирован **не туда**, куда postgres реально пишет. |
| `divergent branches` при pull | Локальная и удалённая ветки разошлись. Решил через `git pull --rebase`, настроил `pull.rebase=true`. |
