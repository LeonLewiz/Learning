```

```

Блок `terraform` → какой провайдер качать, `provider "yandex"` → как подключаться, ресурсы → что создать. Плюс провайдер `hashicorp/local` для генерации файла.

## Ресурсы и квота

Сеть и подсеть создать **не получилось** - `Quota limit vpc.networks.count exceeded`. В папке уже есть `default` с четырьмя подсетями (a/b/d/e).

Решение: не создавать своё, а **прочитать существующее** через `data`:

```hcl
data "yandex_vpc_subnet" "default_a" {
  name = "default-ru-central1-a"
}
```

`resource` = построить, `data` = узнать адрес готового. У меня в конфиге уже был `data` для образа, тот же механизм.

## for_each - два ВМ одним блоком

Копипастить блок ВМ три раза долго. Сделал через `for_each` по map:

```hcl
locals {
  vms = {
    managed1 = { cores = 2, memory = 2, zone = "ru-central1-a" }
    managed2 = { cores = 2, memory = 2, zone = "ru-central1-a" }
  }
}

resource "yandex_compute_instance" "vm" {
  for_each = local.vms
  name     = "devops-study-${each.key}"
  ...
}
```

Параметры ВМ: `standard-v3`, 2 vCPU 20%, 2 GB RAM, диск 15 GB network-ssd, `nat = true` для публичного IP. Ключ заливается через `metadata.ssh-keys` формата `"логин:pubkey"`.

## Решение: control остаётся локально

Сначала были 3 ВМ в облаке, вместе с control. Потом убрал - **control-node оставил на VMware**.

Причина: control это **инструмент**. На нём Ansible, Terraform, vault, tfstate, дашборды. Держать его в облаке = платить лишние деньги, терять всё при `destroy` и завозить vault-пароль руками после каждого `apply`.

## Outputs и мост в Ansible

Output с публичными IP:

```hcl
output "vm_external_ips" {
  value = {
    for k, v in yandex_compute_instance.vm :
    k => v.network_interface[0].nat_ip_address
  }
}
```

Форма `for` в HCL: `{ for ключ, значение in map : новый_ключ => новое_значение }`. `network_interface` - список, поэтому `[0]`.

Мост Terraform → Ansible через `templatefile` + `local_file`: `apply` сам создает `hosts.ini`.

```
[managed]
%{ for k, v in vms ~}
${k} ansible_host=${v.network_interface[0].nat_ip_address} ansible_user=ubuntu
%{ endfor ~}
```

Цепочка замкнулась: `Terraform создал ВМ → output → hosts.ini → Ansible`.

## Мониторинг - убрал хардкод IP

Таргеты в Prometheus смотрели на старые локальные IP (192.168.13.x). В облаке адреса другие → в `/targets` не появились.

Причина: в `prometheus.yml.j2` IP были вписаны вручную. Починил - таргеты теперь берутся из инвентаря:

```
{% for host in groups['managed'] %}
{% set ip = hostvars[host]['ansible_host'] %}
          - '{{ ip }}:8080'
{% endfor %}
```

## Итог

Освоил цикл `init → plan → apply → destroy`. `plan` ловит ошибки кода и прав, `apply` - ошибки в облаке (квоты, мощности).
